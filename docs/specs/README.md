# Design Specs

Design specs live in this directory when a major feature, API shape, transport,
protocol, or architecture decision needs a durable pre-implementation record.

Use this naming convention:

```text
YYYY-MM-DD-<topic>-design.md
```

Specs should capture the intended behavior, interfaces, constraints,
non-goals, and acceptance checks. Write them as stable design references, not
as investigation logs. Implementation checklists belong in `docs/plans/`, and
final current-state reference material belongs in the relevant top-level docs
file.
